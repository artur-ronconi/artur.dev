# Projeto: Portfólio Profissional de Engenharia de Software

Quero que você desenvolva um site completo para meu portfólio profissional como Engenheiro de Software, com foco em Backend, Cloud Computing, AWS, DevOps e desenvolvimento de sistemas distribuídos.

**Não quero um portfólio genérico, com aparência de template pronto.** Quero uma experiência visual excepcional, moderna, interativa e profissional, que demonstre minhas competências técnicas, minha experiência em projetos reais e minha capacidade de desenvolver sistemas robustos.

O resultado deve transmitir a imagem de um desenvolvedor experiente, com domínio de arquitetura de software, infraestrutura em nuvem, desenvolvimento backend e tecnologias modernas.

## 1. Direção visual e identidade

Crie uma identidade visual própria, com forte apelo visual e acabamento de alto nível.

O design deve apresentar:

- Interface moderna, inspirada em dashboards técnicos, ambientes de desenvolvimento, ferramentas de engenharia de software e produtos SaaS premium.
- Tipografia marcante, hierarquia visual bem definida e excelente legibilidade.
- Animações fluidas e microinterações que valorizem a navegação sem prejudicar o desempenho.
- Elementos visuais que representem arquitetura de software, conexões entre serviços, infraestrutura cloud, APIs, bancos de dados e pipelines de CI/CD.
- Cards de projetos visualmente ricos, com imagens, diagramas, tecnologias e informações relevantes.
- Uso inteligente de espaços, grids, contraste, profundidade e elementos gráficos.
- Layout totalmente responsivo, com atenção especial a desktop e dispositivos móveis.

Pode utilizar um tema escuro como base, com cores de destaque bem escolhidas, desde que exista consistência visual em todo o projeto.

Evite completamente:
- Layout genérico de landing page.
- Excesso de gradientes e efeitos neon sem propósito.
- Emojis utilizados como substitutos de ícones profissionais.
- Cards simples contendo apenas título, descrição e botão.
- Animações exageradas ou que prejudiquem a usabilidade.
- Informações fictícias apresentadas como se fossem experiências reais.
- Textos genéricos que poderiam pertencer ao portfólio de qualquer desenvolvedor.

O site deve parecer um produto profissional cuidadosamente projetado, não apenas um currículo convertido em página web.

## 2. Página inicial do portfólio

A página inicial deve apresentar minha identidade profissional de maneira clara e impactante.

Inclua:

### Hero section

Uma primeira seção visualmente impressionante, contendo:
- Meu nome e título profissional.
- Uma apresentação curta e objetiva.
- Destaque para minha atuação em Backend, AWS, arquitetura de sistemas e DevOps.
- Botões para visualizar projetos, acessar meu GitHub e entrar em contato.
- Elementos visuais interativos relacionados a código, serviços cloud ou arquitetura de sistemas.

Utilize textos editáveis pelo painel administrativo sempre que fizer sentido.

### Tecnologias principais

Crie uma seção visual para demonstrar as tecnologias que utilizo profissionalmente.

Dê destaque especialmente a:

**Backend**
- Node.js
- TypeScript
- NestJS
- JavaScript
- APIs REST
- Arquitetura de sistemas distribuídos

**Cloud e DevOps**
- Amazon Web Services (AWS)
- Docker
- Terraform
- GitHub Actions
- Linux
- CI/CD
- Infraestrutura como código
- Serverless

**Frontend**
- React
- Next.js
- HTML
- CSS

**Bancos de dados e mensageria**
- SQL
- DynamoDB
- Sistemas de mensageria e processamento assíncrono

Essas tecnologias devem ser organizadas visualmente por categorias, utilizando ícones oficiais quando disponíveis, indicadores visuais, pequenas descrições e composições interessantes.

Não apresente todas as tecnologias com níveis de proficiência arbitrários. Quero destacar minhas ferramentas principais sem inventar métricas.

As tecnologias e suas categorias devem ser gerenciáveis pelo painel administrativo.

### Experiência e resultados

Crie uma seção que permita destacar experiências profissionais e resultados concretos.

Um exemplo de experiência relevante é minha participação em uma migração de infraestrutura para AWS na UTMify, que contribuiu para suportar aproximadamente 100 mil webhooks mensais.

Esse tipo de resultado deve receber destaque visual, mas todos os números, textos e detalhes precisam ser editáveis pelo administrador.

Não invente outros resultados, empresas, cargos, números ou experiências.

### Projetos em destaque

A página inicial deve apresentar uma seleção dos melhores projetos, com cards personalizados e visualmente ricos.

Cada card deve poder conter:
- Imagem de capa ou screenshot.
- Nome do projeto.
- Descrição resumida.
- Tecnologias utilizadas.
- Categoria do projeto.
- Principais funcionalidades.
- Destaque para desafios técnicos ou resultados.
- Links para demonstração, repositório ou estudo de caso, quando disponíveis.

Os projetos devem ser cadastrados no admin, sem necessidade de editar código para adicionar novos projetos.

Inclua um botão para acessar a página completa de projetos.

### Outras seções

Inclua também:
- Sobre mim.
- Experiência profissional.
- Certificações AWS.
- Contato.
- Links para GitHub, LinkedIn e outros perfis profissionais.

Todas as informações pessoais e profissionais relevantes devem ser editáveis pelo painel administrativo.

## 3. Página individual de cada projeto — prioridade máxima

Esta é uma das partes mais importantes do sistema.

**Não quero que cada projeto seja apenas um card com uma descrição. Quero que cada projeto tenha sua própria página de apresentação, com aparência de um estudo de caso técnico profissional.**

Cada projeto deve possuir uma URL própria, amigável e permanente, por exemplo:

`/projetos/nome-do-projeto`

Cada página precisa apresentar perfeitamente as informações cadastradas no painel administrativo, com um layout que valorize tanto o conteúdo quanto a complexidade técnica do projeto.

Crie uma estrutura que permita apresentar:

1. **Apresentação visual:** imagem de capa, nome, descrição, categoria e links relevantes.
2. **Contexto e problema:** qual problema o projeto buscava resolver.
3. **Minha contribuição:** responsabilidades, decisões e partes que desenvolvi pessoalmente.
4. **Solução implementada:** como o sistema funciona e quais abordagens foram utilizadas.
5. **Arquitetura:** diagramas, componentes, serviços, integrações, fluxos de dados e comunicação entre sistemas.
6. **Tecnologias utilizadas:** logos, categorias e explicações sobre o papel de cada tecnologia.
7. **Desafios técnicos:** problemas relevantes encontrados e como foram resolvidos.
8. **Resultados:** métricas, ganhos de desempenho, escalabilidade, disponibilidade ou outros resultados reais, quando existirem.
9. **Imagens e demonstrações:** screenshots, diagramas, vídeos ou galerias.
10. **Links externos:** repositório GitHub, aplicação publicada, documentação ou outros materiais, quando disponíveis.
11. **Navegação entre projetos:** sugestões de outros projetos relacionados.

Nem todos os projetos terão todas essas informações. A página deve adaptar sua apresentação aos campos preenchidos, ocultando seções vazias sem deixar espaços quebrados ou elementos visualmente incompletos.

### Diferencial visual das páginas de projetos

Cada projeto deve aproveitar seus próprios conteúdos para construir uma apresentação visual única.

Por exemplo:
- Um projeto de infraestrutura AWS pode mostrar um diagrama de arquitetura cloud.
- Uma API pode apresentar endpoints, integrações e fluxos de requisição.
- Um sistema distribuído pode mostrar serviços, filas, eventos e bancos de dados.
- Um projeto frontend pode apresentar screenshots de diferentes telas.
- Uma automação DevOps pode apresentar um pipeline de CI/CD.

Implemente componentes visuais reutilizáveis para essas diferentes apresentações.

Se possível, permita cadastrar diagramas de arquitetura por meio de um editor visual ou de um formato estruturado, como Mermaid, com renderização segura e visualmente integrada ao site.

O objetivo é permitir que recrutadores, desenvolvedores e líderes técnicos compreendam rapidamente o que foi construído, como funciona e quais decisões técnicas tornam o projeto relevante.

## 4. Painel administrativo completo

Desenvolva uma área administrativa privada, acessível por uma rota como `/admin`.

Esse painel deve ser funcional de verdade. Não quero uma interface demonstrativa com botões que não fazem nada.

### Autenticação e segurança

- Login administrativo.
- Rotas administrativas protegidas no servidor.
- Senhas armazenadas de forma segura, utilizando hash apropriado.
- Sessões seguras e proteção contra acesso não autorizado.
- Validação de permissões no backend, não apenas no frontend.
- Proteção contra ataques comuns, como XSS, CSRF e tentativas de login abusivas, conforme aplicável à arquitetura escolhida.
- Segredos e credenciais mantidos em variáveis de ambiente ou serviços apropriados.
- Não permitir cadastro público de administradores.

Não crie uma senha fixa ou uma autenticação fictícia apenas para simular o painel.

### Dashboard

Crie uma tela inicial administrativa com informações úteis, como:
- Total de projetos cadastrados.
- Projetos publicados e rascunhos.
- Projetos destacados na página inicial.
- Últimos projetos atualizados.
- Atalhos para cadastrar projetos e editar informações do portfólio.

Não invente métricas de visitantes ou acessos se não houver um mecanismo real para coletá-las.

### CRUD de projetos

Implemente todas as operações necessárias:
- Criar projeto.
- Editar projeto.
- Visualizar prévia.
- Publicar e despublicar.
- Salvar como rascunho.
- Excluir com confirmação.
- Duplicar projeto, se possível.
- Ordenar projetos.
- Marcar projetos como destaque.
- Gerenciar categorias e tecnologias.

O cadastro deve ter uma interface intuitiva, organizada em etapas ou abas, evitando um formulário gigantesco e confuso.

### Campos do projeto

Cada projeto deve suportar, no mínimo:

**Informações gerais**
- Título.
- Slug para URL.
- Subtítulo.
- Descrição curta.
- Descrição completa.
- Categoria.
- Status: rascunho ou publicado.
- Destaque na página inicial.
- Ordem de exibição.
- Data do projeto, quando relevante.

**Mídia**
- Imagem de capa.
- Screenshots.
- Galeria de imagens.
- Vídeos ou links para demonstrações.
- Texto alternativo das imagens.

**Conteúdo técnico**
- Contexto e problema.
- Objetivos.
- Minha contribuição.
- Solução implementada.
- Arquitetura.
- Desafios técnicos.
- Decisões de engenharia.
- Resultados e métricas.
- Aprendizados.

**Tecnologias**
- Seleção de tecnologias previamente cadastradas.
- Possibilidade de cadastrar uma nova tecnologia.
- Organização por categorias.
- Descrição do papel de cada tecnologia no projeto.

**Diagramas e documentação**
- Cadastro de diagramas de arquitetura.
- Blocos de código com destaque de sintaxe, quando necessário.
- Documentação complementar.
- Endpoints ou integrações relevantes, quando apropriado.

**Links**
- Repositório.
- Aplicação publicada.
- Documentação.
- Vídeo demonstrativo.
- Outros links relevantes.

**SEO**
- Meta title.
- Meta description.
- Open Graph image.
- Slug.
- Indexação habilitada ou desabilitada.

O administrador deve conseguir montar uma página completa e visualmente rica sem precisar alterar arquivos de código.

### Pré-visualização

Implemente uma prévia real da página do projeto antes da publicação.

A prévia deve reproduzir o layout público, permitindo verificar textos, imagens, diagramas, ordem das seções e aparência geral.

Se necessário, implemente um mecanismo de preview autenticado para projetos em rascunho.

### Gerenciamento do restante do portfólio

Além dos projetos, o painel deve permitir editar:
- Nome e apresentação profissional.
- Foto ou avatar.
- Resumo profissional.
- Experiências profissionais.
- Certificações.
- Tecnologias e categorias.
- Links sociais.
- Informações de contato.
- Conteúdo da página inicial.
- Ordem e visibilidade das seções.

## 5. Arquitetura e tecnologias

Minha principal especialidade é desenvolvimento backend com Node.js e TypeScript, além de experiência com AWS, cloud e DevOps.

Prefiro uma solução moderna, sustentável, bem estruturada e fácil de manter.

Considere uma arquitetura utilizando:
- Next.js com TypeScript para a aplicação.
- React para os componentes de interface.
- Uma camada backend bem definida para regras de negócio, autenticação e persistência.
- PostgreSQL para os dados estruturados, caso não exista uma razão técnica forte para escolher outra opção.
- ORM com tipagem e migrations.
- Armazenamento de imagens em serviço de objetos compatível com S3.
- Validação de dados compartilhada ou consistente entre frontend e backend.
- Biblioteca de componentes e ícones profissionais.
- Testes automatizados.
- Docker para ambiente local, quando apropriado.

Você pode escolher bibliotecas adicionais para animações, diagramas, formulários, edição de conteúdo e visualização de código.

Não adicione tecnologias apenas para tornar a stack aparentemente mais impressionante. Cada dependência deve ter uma função clara.

Se optar por uma aplicação full-stack em Next.js, mantenha a arquitetura organizada por domínios e responsabilidades, sem espalhar regras de negócio por componentes de interface.

A aplicação deve estar preparada para uma futura publicação na AWS, preferencialmente com infraestrutura e deploy documentados.

## 6. Modelagem dos dados

Modele os dados de forma consistente.

Considere entidades como:
- Project.
- Technology.
- TechnologyCategory.
- ProjectImage.
- ProjectSection ou estrutura equivalente de conteúdo.
- ProfessionalExperience.
- Certification.
- PortfolioSettings.
- AdminUser.

A estrutura final pode ser diferente, desde que permita gerenciar projetos complexos sem duplicar informações desnecessariamente.

Considere relações muitos-para-muitos entre projetos e tecnologias.

As páginas públicas devem buscar seus conteúdos do banco de dados. Não quero que os projetos sejam cadastrados manualmente em arrays estáticos no frontend.

Implemente migrations, constraints, índices e validações apropriadas.

## 7. Qualidade, acessibilidade e desempenho

O resultado deve atender a critérios de qualidade de produção:

- Layout responsivo e consistente.
- Acessibilidade por teclado.
- HTML semântico.
- Contraste adequado.
- Estados de carregamento.
- Tratamento de erros.
- Estados vazios bem desenhados.
- Otimização de imagens.
- Carregamento eficiente de páginas.
- SEO técnico.
- URLs amigáveis.
- Validação no cliente e no servidor.
- Tratamento correto de erros de banco de dados.
- Proteção dos dados administrativos.
- Testes para as principais funcionalidades.

Evite que animações, imagens pesadas ou bibliotecas desnecessárias prejudiquem a experiência.

## 8. Regras de implementação

Quero que você desenvolva o projeto de verdade, não apenas produza um plano ou uma interface visual.

Siga esta ordem:

1. Analise o repositório atual e identifique a stack, as dependências e o que já existe.
2. Defina a arquitetura, a modelagem dos dados e a estrutura de páginas.
3. Construa primeiro a identidade visual e os componentes fundamentais.
4. Implemente a página inicial e as páginas individuais de projetos.
5. Implemente o backend, a persistência e a autenticação administrativa.
6. Construa o painel de administração e todos os fluxos de CRUD.
7. Integre o conteúdo dinâmico do banco de dados às páginas públicas.
8. Implemente preview, publicação, gerenciamento de imagens e SEO.
9. Adicione testes, validações e tratamento de erros.
10. Execute a aplicação, verifique os fluxos principais e corrija os problemas encontrados.

Se o repositório estiver vazio, inicialize o projeto adequadamente. Se já existir uma aplicação, preserve o que estiver funcionando e adapte a implementação sem sobrescrever desnecessariamente o código existente.

Não deixe funcionalidades essenciais simuladas, com dados hardcoded ou com botões sem ação.

Se uma integração exigir credenciais externas, implemente a integração corretamente, documente as variáveis necessárias e informe o que depende de configuração externa.

## 9. Dados de demonstração e conteúdo real

Cadastre alguns projetos de demonstração apenas para facilitar a avaliação visual e funcional durante o desenvolvimento.

Identifique claramente os dados fictícios e permita removê-los facilmente.

Não invente experiências profissionais, resultados, empresas ou métricas atribuídas a mim.

Deixe os dados pessoais e profissionais preparados para preenchimento pelo painel administrativo.

## 10. Critérios de conclusão

Considere o projeto concluído somente quando:

- A página inicial tiver identidade visual marcante e profissional.
- As principais tecnologias estiverem apresentadas visualmente.
- Cada projeto publicado possuir sua própria página detalhada.
- Os conteúdos cadastrados no admin forem refletidos corretamente no site.
- For possível criar, editar, publicar, despublicar e excluir projetos.
- O administrador conseguir gerenciar imagens, tecnologias, links e conteúdo técnico.
- A pré-visualização funcionar antes da publicação.
- As rotas administrativas estiverem protegidas no servidor.
- O sistema persistir os dados em um banco real.
- Não houver botões importantes sem funcionalidade.
- Os layouts funcionarem em desktop e dispositivos móveis.
- Os fluxos principais tiverem sido testados.
- Existirem instruções claras para executar localmente e publicar a aplicação.

**Prioridade absoluta:** combine uma apresentação visual de alto nível com um sistema de gerenciamento realmente funcional. Quero que o portfólio seja capaz de apresentar projetos de engenharia de software com profundidade técnica, e que eu consiga administrar todo o conteúdo sem precisar modificar o código-fonte.

Antes de finalizar, revise o resultado como se você fosse um recrutador técnico avaliando o portfólio e como se fosse um engenheiro responsável por manter a aplicação em produção. Corrija os problemas visuais, técnicos e de usabilidade que encontrar.
